## Пользователи и доступ

При открытии приложения доступны регистрация и вход по логину и паролю.
Регистрация всегда создаёт пользователя с ролью `USER`. Пользователь видит и
изменяет только свои организации, адреса, координаты и локации. Администратор
(`ADMIN`) видит все данные и список пользователей, но изменяет и удаляет только
свои объекты. Связывать объекты разных владельцев нельзя. Специальные операции
считаются по доступным пользователю организациям.

Чтобы назначить администратора, сначала зарегистрируйте аккаунт, затем выполните
в БД команду, подставив его логин:

```sql
update app_user set role = 'ADMIN' where login = 'your_login';
```

После назначения обновите страницу. Роль проверяется по БД при каждом запросе,
клиент не может назначить её при регистрации или через JWT.

Перед запуском обновлённого приложения выполните `./gradlew setupDb`: скрипт
создаёт `app_user`, добавляет `owner_id` в четыре таблицы и обновляет функции БД.
Повторный запуск сохраняет данные. Старые и тестовые записи без владельца доступны
только администратору для чтения. Новым записям, включая YAML-импорт, владелец
назначается сервером. В импортируемом файле не нужно указывать `id` и `ownerId`.

REST API:

* `POST /api/auth/register` и `POST /api/auth/login`: JSON `{"login":"student","password":"password123"}`.
  Ответ содержит `token` и `user` (`id`, `login`, `role`).
* `GET /api/auth/me`: текущий пользователь.
* `GET /api/users`: список пользователей, только для администратора.
* Остальные API требуют заголовок `Authorization: Bearer <token>`.
* Без действительного токена возвращается `401`; изменение чужих данных администратором
  или доступ обычного пользователя к списку пользователей возвращает `403`.
  Недоступные обычному пользователю ID возвращают `404`.

Пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной солью и 600 000 итераций.
JWT действует один час. Для постоянного ключа задайте переменную окружения
`JWT_SECRET` перед запуском WildFly: Base64 от случайных 32 байт или больше.
Например, в PowerShell:

```powershell
$jwtKey = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($jwtKey)
$rng.Dispose()
$env:JWT_SECRET = [Convert]::ToBase64String($jwtKey)
./gradlew.bat up
```

Без `JWT_SECRET` сервер создаёт случайный ключ при запуске, поэтому после
перезапуска нужно войти снова. Браузер хранит токен в `sessionStorage` текущей
вкладки; выход удаляет его. Уже выданный токен действителен до истечения срока.
Внешний доступ к приложению следует предоставлять по HTTPS.

WebSocket `/updates` принимает JWT первым текстовым сообщением. Уведомления
отправляются владельцу изменённых данных и администраторам после коммита.

## Проверка

```text
./gradlew test
./gradlew test -PpostgresTests
```

Второй вариант дополнительно проверяет миграцию, Criteria-запросы и SQL-функции
на PostgreSQL из `config/local.properties`. Тесты создают отдельную временную
схему `auth_test_*` и удаляют её после проверки, рабочие таблицы не меняются.
